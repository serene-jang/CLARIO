# Device Client: 일회성 페어링·상태·링크 전달

## 현재 범위

2026-10-18 로컬 구현. 기존 Google 교사/관리자 로그인과 기기 명부를 확장한다.

- 5분 동안 유효한 128비트 무작위 일회성 연결 코드. 서버에는 해시만 저장한다.
- 별도 기기 토큰: 서버 해시 저장, 30일 유효, 웹 사용자 API에 사용할 수 없다.
- 새 코드 발급 시 이전 연결을 폐기한다. 교사/관리자의 연결 권한 해제와 학생 측 연결 해제를 지원한다.
- Manifest V3 확장 프로그램이 startup/설치·30초 alarm·수동 확인으로 서버에 접속한다.
- 서버가 받은 heartbeat를 기준으로 90초 이내는 온라인, 초과는 오프라인으로 표시한다. 교사 화면은 15초마다 재조회한다.
- 링크 전달 대상은 발송 시점의 학급 등록 기기다. 오프라인 기기에는 7일 이내 재연결 시 다시 제공한다.
- 자료 수신과 학생이 링크를 열도록 요청한 상태를 별도 확인한다. “열기”는 탭 생성 요청 성공이지 외부 사이트의 로딩/읽기 완료 증명이 아니다.
- 학생에게는 팝업 자료 목록과 확장 프로그램 배지의 새 자료 수를 제공한다. OS 알림/자동 탭 열기는 하지 않는다.
- 자료 삭제 시 이후 조회·열기를 거부한다. 이미 열린 탭을 원격으로 닫지는 않는다.
- 사용자가 선택한 **자율 집중 안내**: 교사/관리자가 학급 안내를 켜고 끄면 학생의 다음 동기화에서 팝업·배지로 표시한다. 웹사이트/앱 차단이나 집중 행동 수집은 하지 않는다. 동기화 실패·오래된 상태는 확인 불가로 표시한다.

**완료가 아닌 것:** 관리형 물리 기기 증명, Google Admin 강제 배포, 실기기 자동 연결 보장, WebSocket 즉시 이벤트, OS 앱/기기 제어, 화면 확인, 녹화·암호화 객체 저장·자동 삭제. 후속 Chrome 프로필 도메인 차단은 아래 별도 범위이며 전 기기 강제 제어가 아니다.

### 후속: 승인 학생 웹 연결과 도메인 차단

확장 0.2.0은 `storage`, `alarms`에 **`declarativeNetRequest`** 권한을 추가한다. 설치/업데이트 시 권한 변경을 검토한다. content script·화면/카메라/마이크·방문 기록 권한은 없다. API 원본에 대한 선택형 호스트 권한만 요청한다.

1. 교사 Google 로그인→교실 관리→승인 학생→수업 시작 후 **사이트 차단 설정 열기**에서 도메인을 저장한다. 최대 50개, 예 `example.com`, 하위 도메인 포함. URL/IP/와일드카드·로컬·설정된 CLARIO 웹/API 자기 차단을 거부한다. 공개 접미사 판별/사이트 안전성 검사는 아니므로 학교가 범위를 확인한다. 빈 목록 저장은 해제다.
2. 학생은 승인된 학생 웹의 **확장 연결 코드 발급**을 누른다. 교실 초대코드/기존 기기 코드와 별개로 5분·일회용·학생당 1분 5회다. 재발급은 이전 확장 자격을 철회한다.
3. 설치된 확장 팝업에서 **학생 웹에서 발급한 확장 연결 코드** 항목을 선택하고 API 원본/코드를 입력·권한 허용한다. 학생별 다른 코드이며 학급 전체 공유/물리 기기 증명이 아니다. 새 토큰은 원래 학생 자격·승인/세대·유휴/절대 만료를 상속하며 확장만 켜 두어 학생 로그인을 무기한 유지하지 않는다.
4. 팝업의 적용 도메인·만료·마지막 확인/오류를 확인한다. 서버 정책·마지막 서버 접속만으로 실제 적용/학생 준수를 주장하지 않는다. 학생 웹의 정책은 수동 재확인이고 확장 팝업은 열려 있는 동안 약 5초마다 상태를 확인한다.
5. 약 30초마다 받은 현재 활성 수업 정책을 DNR **session rules**로 적용한다. 지정 도메인과 하위 도메인의 새 `main_frame`/`sub_frame` 요청만 차단하며 다른 리소스·이미 열린 내용/탭·다른 프로필/브라우저·앱은 통제하지 않는다. 방문 URL/학생 행동은 기록하지 않는다.
6. 수업 종료/목록 해제는 다음 sync에 반영한다. 자격 철회·참여 종료·교실 종료는 다음 서버 요청에서 거부하고 규칙을 지운다. 연결 오류도 해제하며, 갱신이 없으면 60초 서버 lease의 alarm에서 해제한다. 브라우저 시작/연결 해제도 자체 규칙만 제거한다. 절전/alarm 지연은 적용·해제를 늦출 수 있어 정확한 벽시계 상한은 아니다. 해제 자체가 실패하면 오류를 표시하고 확장 비활성화/재시도를 안내한다.

학교가 강제 설치·삭제 방지·다른 브라우저 제한을 원하면 관리자 승인·관리 정책·실제 Chromebook 검증이 따로 필요하다. 일반 확장은 제거/비활성화할 수 있다. 이번 작업은 스토어 게시·관리 배포를 하지 않았다.

| 후속 API | 경계 |
|---|---|
| `GET/PATCH /api/identity/classrooms/:id/blocking` | 교실 관리자, `{domains}` 목록, 변경 감사 |
| `GET /api/student/blocking` | 승인 학생 쿠키, 본인 정책/확장 마지막 접속 |
| `POST /api/student/browser-code` | 동일 원본·CSRF·승인 자격, 이전 연결 철회/코드 감사 |
| `POST /api/browser-device/pair` | 학생 웹 일회용 코드→별도 확장 토큰, 페어링 감사 |
| `POST /api/browser-device/sync` | 현재 학생 자격/세대 재검사, 집중 안내와 활성 수업 차단 lease. 링크/PDF는 학생 웹에서 제공 |
| `POST /api/browser-device/disconnect` | 해당 확장 토큰 철회/감사 |

기존 기기 `/sync`에도 `blocking`이 추가되지만 기존 자료/집중 계약은 유지한다. 확장 토큰을 교사 bearer/학생 쿠키/기존 기기 토큰으로 재사용할 수 없다. `chrome-extension://` CORS는 `/api/device`·`/api/browser-device`에만 허용하며 인증 대안이 아니다.

## 준비 및 설치

1. 기존 [인증 설정](./phase-2-authentication.md)에 따라 실제 학교 OAuth·DB·승인 계정·학급·학생을 준비한다.
2. API 중단/백업 절차를 확인한 뒤 `npm run db:migrate --workspace @clario/server`로 현재 버전 **12**까지 적용한다. 기기/집중 안내는 버전 3/4에서 도입했으며 기존 버전을 수정하지 않는다. 무계정 학생 저장·신청 제한·자료 수신/삭제 요청은 기기 인증을 대체하지 않는다.
3. API·교사 앱을 실행한다. 학교 관리자/담당 교사만 학급 관리에서 기기를 등록하고 연결 코드를 발급할 수 있다.
4. 학교 승인 시험용 Chrome/Chromebook의 `chrome://extensions`에서 개발자 모드 → 압축해제된 확장 프로그램 로드 → `apps/device-extension`을 선택한다.
5. 관리 정책이 개발자 모드/확장 설치를 금지하면 우회하지 않는다. 관리자가 시험 OU·고정 확장 ID·스토어/관리 배포를 준비해야 한다. 이번 작업은 Chrome Web Store 게시/학교 강제 배포를 수행하지 않았다.
6. 확장 프로그램을 고정하고 팝업을 연다. 교사가 알려준 **API 원본**과 32자리 코드를 입력한다. 교사 웹 주소가 아니라 API 서버 주소다.
7. 해당 API 원본에만 선택적으로 호스트 접근 권한을 허용한다. HTTPS만 허용하며 개발 시에만 `localhost`/`127.0.0.1` HTTP를 허용한다.
8. 연결된 기기 이름·자료 목록·배지와 교사 화면 상태를 확인한다. 코드가 만료되었거나 사용되었으면 새 코드를 발급한다.

학교 장비가 아닌 설치 프로필에도 코드 소지자가 연결할 수 있다. 코드를 학생 게시판이나 학급 전체에 공유하지 말고 해당 기기에서만 입력한다. 등록 교사는 실제 기기/학생/자산번호를 확인해야 한다.

## 자격 증명과 상태

- 확장 프로그램 `storage.local`에 토큰을 보관하고 `TRUSTED_CONTEXTS`로 제한한다. content script는 없고 popup 메시지 발신 경로를 제한한다.
- `storage.local`은 하드웨어 보호된 암호화 비밀 저장소가 아니다. 프로필/기기 복제·공유 시 토큰이 복사될 위험이 있어 학교 승인된 시험 환경에서만 사용한다. `storage.sync`에는 넣지 않는다.
- 토큰이 30일 뒤 만료되면 자동 무기한 연장이 아니라 새 코드로 등록해야 한다.
- 서버가 401을 반환하면 로컬 토큰/자료 캐시를 지우고 주기 연결을 중단한다. 네트워크 오류는 상태 확인 불가로 표시하고 다음 alarm에서 재시도한다.
- 절전·로그아웃·프로필 종료·OS 업데이트·alarm 지연에서 정확한 30초 접속을 보장하지 않는다. 화면의 마지막 수신 시각을 함께 확인한다.
- 사용자 중지/역할 변경·학급 보관·학생 제외/기기 삭제 시 서버가 후속 기기 요청을 차단한다.
- 일반 `chrome-extension://` 원본은 기기 API 경로에서만 CORS를 허용한다. 이는 신뢰 증거가 아니며 각 요청에 별도 코드/기기 인증이 필요하다. 웹 사용자 API에는 이 예외를 적용하지 않는다.
- 현재 요청 제한은 프로세스별 socket 주소 기반으로 1분 600회다. 프록시 뒤 다수 기기·다중 API 인스턴스용 전역 속도 제한은 후속 작업이다. 소규모 시험용이며 대규모 운영 준비 완료로 보지 않는다.

## 데이터·API

마이그레이션 3: `device_pairings`, `registered_devices`의 토큰 해시/만료/heartbeat 열, `class_materials`, `material_deliveries`.

마이그레이션 4: `classes.voluntary_focus` (기본 꺼짐). 모드 변경은 `focus.started`/`focus.ended` 감사 기록을 남긴다. 현재 API 시작에는 버전 12까지 필요하다. 버전 10은 실제 boolean 변경에만 버전/시각을 올리므로 기존 API·확장과 새 학생 웹이 단일 상태를 공유한다. 버전 11의 학생 삭제 요청은 정책 승인 대기와 접근 철회이며 기기/실제 데이터 삭제 완료가 아니다. 버전 12는 PDF 메타데이터·파일 대상 감사·수업 차단 도메인·승인 학생 확장 자격을 추가한다.

| 경로 | 인증/동작 |
|---|---|
| `POST /api/device/pair` | 단일 사용 코드 교환, 기존 기기 토큰을 대체 |
| `POST /api/device/sync` | 기기 토큰, heartbeat 및 현재 자료 목록 |
| `POST /api/device/materials/:id/ack` | 기기 토큰, 자신의 자료만 `received`/`opened` 기록 |
| `POST /api/device/disconnect` | 기기 토큰 폐기 |
| `POST /api/classes/:classId/devices/:deviceId/pairing` | 담당 교사/관리자, 새 코드 발급·이전 토큰 폐기 |
| `DELETE /api/classes/:classId/devices/:deviceId/connection` | 담당 교사/관리자, 코드·연결 토큰 폐기 |
| `GET/POST /api/classes/:classId/materials` | 담당 교사/관리자, 자료/전달 상태 조회·발송 |
| `DELETE /api/classes/:classId/materials/:id` | 담당 교사/관리자, 자료 및 전달 상태 삭제 |
| `GET/PATCH /api/classes/:classId/focus` | 담당 교사/관리자, 자율 집중 안내 조회·변경. 변경 본문 `enabled`는 boolean |

링크는 인증 정보 없는 HTTPS URL만 받고 서버에서 외부 URL을 가져오지 않는다. 자료의 사이트 안전성·적합성을 학교가 확인해야 한다. 리다이렉트 이후 사이트까지 자동 검증하는 기능은 아니다.

자료는 7일 이후 접근 불가가 되지만 **DB 원본의 자동 삭제를 구현한 것은 아니다.** 수동 자료 삭제는 메타데이터/전달 기록을 삭제한다. 접속 로그 및 기타 메타데이터의 학교별 보관/삭제 정책은 후속 승인·구현이 필요하다.

### 7단계 학생 웹 자료와의 구분

8단계 새 웹 자율 집중 안내는 교사 5초/학생 10초 전체 조회로 제공한다. 새 교사 변경에는 현재 수업 ID/예상 버전이 필요하며 수업/교실 종료 시 해제, 다음 수업 꺼짐이다. 기존 `/api/classes/:classId/focus`의 `{enabled}`/204 및 확장 배지·팝업/동기화 계약은 유지한다. 새 웹에서 수업이 없으면 꺼짐으로 표시하며 학생 준수/수신 확인·강제 차단은 하지 않는다.

`/api/identity/classrooms/:id/materials`의 교사 등록/목록/삭제는 같은 `class_materials`를 사용한다. 등록 시 기존 학급 등록 기기의 발송 시점 전달 스냅샷도 생성한다. 기존 학교 작업공간 자료 API로 만든 링크도 현재 승인 학생이 같은 교실에서 조회할 수 있으며 학생 이름/학번으로 기기를 자동 연결하지 않는다.

학생 웹 `/api/student/materials`는 현재 승인된 참여 쿠키를 매번 검증한다. 10초 목록 조회 뒤 최대 50개 `/received` 확인과 명시적 자료별 `/open` 요청을 처리한다. 버전 9 `classroom_material_receipts`는 기기 `material_deliveries`와 독립이며 교사 웹 수신 집계도 학생 참여자 기준이다. 기기 ack를 학생 웹 수신으로 옮기거나 학생 웹 수신을 기기 온라인/읽기 완료로 표시하지 않는다.

자료 삭제는 두 종류 수신 기록을 cascade 삭제하고 감사를 유지한다. 학생 웹은 등록 후 승인된 학생도 유효 자료를 조회할 수 있지만 기기는 기존 발송 대상 스냅샷 계약을 유지한다. 수업 종료 후 유효 학생 자격/자료는 남고 교실 종료나 자격 철회 시 학생의 새 접근은 차단된다. 확장 설치/실기기 검증 상태는 이번 웹 자료 구현으로 바뀌지 않는다.

### 9A 관리자 실행 순서 — 화면을 수집하지 않음

학교가 승인한 시험 OU·프로필·합성 학생/자산만 사용한다. 학생 실명·학번·이메일·일련번호를 이 문서/저장소에 기록하지 않는다. 시험 관리자 계정의 비밀번호, 세션·기기 토큰, 초대/페어링 코드, 전체 `chrome://policy` 내보내기나 정책 스크린샷을 공유하지 않는다.

1. 관리자가 시험 일시·ChromeOS/Chrome 버전·관리 여부·설치 허용 정책·승인된 HTTPS API 원본·결과 담당자를 학교 내부에 기록한다. 정책 위반 우회/개발자 모드 강제 전환은 하지 않는다. 개발 설치가 금지되면 학교 관리 배포 준비까지 보류한다.
2. 기존 기기 명부는 **기존 학교 작업공간의 승인된 교사/학생 계정**을 사용한다. 새 독립 교사의 무계정 학생 교실과 자동 연결하지 않는다. 시험용 기기를 기존 명부에 등록하고 관리자/담당 교사가 실제 자산을 확인한다. Google 로그인만으로 학교 관리자 역할을 만들지 않는다.
3. 위 설치 절차로 확장을 준비한다. 현재 권한은 `storage`·`alarms`, 필요 시 사용자가 지정한 API 원본 호스트뿐인지 확인한다. 화면/카메라/마이크/방문 기록 접근 허용을 요구하면 중단한다. 선택 호스트 목록의 `https://*/*`는 요청 가능한 범위이며 모든 사이트 권한을 상시 부여한다는 뜻이 아니다.
4. 해당 기기에만 전달한 일회성 코드로 연결한다. 연결 후 팝업의 기기 이름·서버 원본·확인 시각과 교사 명부의 마지막 서버 heartbeat가 일치하는지 비교한다. 같은 코드를 두 번째 프로필에서 재사용하면 거부돼야 한다. 학교 정책이 API 호스트 권한을 거부하면 명시적 오류만 표시되고 연결 성공으로 표시되지 않아야 한다.
5. 합성 HTTPS 자료 한 개를 발송한다. 명시적으로 열기 전 자동 탭이 생기지 않는지, 다른 학급/발송 대상이 아닌 기기에 자료가 보이지 않는지 확인한다. 집중 안내는 배지/팝업 문구뿐이고 사이트·다른 앱은 차단하지 않아야 한다. 자료 열기 요청은 읽기 완료가 아니다.
6. 네트워크를 끊고 확장 수동 확인을 실행한다. 확인 불가·자료 캐시 제거를 확인하고, 마지막 서버 heartbeat에서 **90초 초과** 후 교사 목록을 새로고침해 오프라인인지 확인한다. 교사 자동 폴링 15초 지연과 네트워크 지연을 구분한다. 이 기준은 학생 웹의 20/45초 기준과 다르다.
7. 네트워크 복구·수동 확인 뒤 최신 서버 상태만 표시되는지 확인한다. Chrome 재시작·ChromeOS 재부팅·잠금/잠금 해제·절전/깨우기를 각각 시험하고, 이전 연결 자격 유지/만료 여부·첫 성공 서버 시각·alarm 지연을 기록한다. 절전 중 30초 주기나 상시 온라인을 합격 조건으로 삼지 않는다. 재시작에서 alarm이 복원되지 않으면 실패로 기록하고 수동 확인 결과와 구분한다.
8. 공유 기기는 별도 시험 프로필을 사용해 이전 학생과 다른 학생을 시험한다. 기기 페어링이 무계정 학생 참여나 실제 사용자 변경을 자동 증명하지 않아야 한다. 프로필/디스크 복제에 대한 토큰 보호를 주장하지 않는다. 자산·교실 배정 변경은 명시적으로 철회 후 재등록한다.
9. 교사 연결 권한 해제 후 이전 확장 자격의 다음 요청이 401이고 토큰/자료/집중 상태 제거·주기 확인 중단이 되는지 확인한다. 기기/학생 제외·계정 중지·교실 보관도 각 시험하며, 다른 담당 교사는 코드 발급·철회·목록 조회가 거부돼야 한다.
10. 시험 종료는 서버 철회부터 수행하고, 확장 연결 해제/제거·허용 호스트 권한 제거·시험 OU 정책 복원·합성 자료/명부 정리를 관리자가 확인한다. 기록/감사의 학교 보관 절차는 따로 적용한다. 화면·영상 파일은 생성하지 않는다.

현재 서비스에는 학교 강제 배포 패키지·Verified Access 통합·관리 정책 설정 도구가 없다. 관리자가 승인한 배포 방식을 확정하기 전 설치 성공을 보장하지 않는다.

### 9B 화면 검증 게이트 — 승인 전 실행 금지

- `getDisplayMedia`는 사용자 동작과 매번 허용·소스 선택이 필요하다. 일반 웹에서 권한을 영구 저장해 교사가 임의의 학생 화면을 자동 수집하는 설계를 하지 않는다. 보안 컨텍스트/Permissions Policy·브라우저/OS·학교 정책을 먼저 확인한다. API 이름이 존재하는 것만으로 지원 완료라 하지 않는다. [S1][S2]
- 확장 `desktopCapture`도 선택 UI와 별도 권한이 필요하고 취소 시 빈 stream ID, 미사용 ID의 짧은 수명·일회 사용 조건이 있다. 현재 확장은 이 권한을 요청하지 않는다. [S3]
- 승인 후 별도 시험: 합성 화면만, 사용자 취소/거절·정책 거절, 브라우저의 공유 중단·권한 철회·탭 종료·연결 단절·학생 차단·교실/수업 종료, 지속 학생 고지·중단/감사까지 확인한다. 거절을 성공으로, 마지막 프레임을 실시간으로 표시하지 않아야 한다.
- 교실별 송신/수신 권한 재검사와 탈퇴 후 새 프레임 차단, 지연·신선도·누락 구간을 실제 측정한다. 합격 임계값(프레임 나이/처리량/수업 규모)은 아직 미결정이다. WebRTC/P2P·TURN/SFU·저장 여부를 현재 확정하지 않는다.

### 9C 녹화 검증 게이트 — 별도 승인·삭제 보장 필요

- 화면 공유 지원이나 `MediaRecorder.isTypeSupported(...)`의 true는 녹화의 법적 승인·실제 자원/저장 성공을 증명하지 않는다. 자원 부족으로도 실패할 수 있다. [S6]
- 승인 전에 학교 책임자가 필요성·처리 근거·대상/목적·학생 고지/필요 승인·열람 역할·수동 삭제/요청 절차를 확인해야 한다. 구체적인 보관 기간/법규 상한은 미결정이며 추정값을 기본값으로 넣지 않는다.
- 별도 후속 시험: 전체 대상과 실제 녹화 학생/구간 분리, 중도 참여/퇴장, 사용자 중단·권한/연결 상실, 인코딩/용량/업로드 실패·재시도·부분 성공, 서버 권한/만료·직접 URL 거부·감사, 전송/저장 암호화.
- 원본·관리 복제본·백업 각각의 보관 상한·삭제 방법/주기·실패 알림/재시도·실제 삭제 확인·복구 후 재삭제를 검증한다. 저장소 lifecycle 설정만으로 삭제 완료를 선언하지 않는다. 대상별 삭제 확인 전에는 삭제 대기다.
- 실제 화면용 파일·비공개 미디어 저장소·녹화 정책/자동 삭제 API는 없다. 따라서 운영 직접 URL·자동 삭제를 실제 검증했다고 보고할 수 없다. 이 게이트가 충족되기 전 실제 학생 화면 녹화는 계속 비활성이다. 아래 합성 시험은 별도다.

### 합성 canvas 로컬 시험 — 9B/9C 승인이 아님

후속으로 실제 화면 선택·무음 녹화의 브라우저 엔진 코드를 작성했으나 현재 UI에서 호출하지 않는다. 사용자는 학교 승인/안내 준비를 밝혔지만 구체 보관 기간/상한·저장소·열람/삭제 조건은 아직 미제공이다. `screen-media`의 서버 정책은 항상 비활성이며 실제 미디어 송신은 403·거부 감사를 남긴다. 대역으로 브라우저 선택 거절/중단/권한 수명·인코더/전송 실패를 검증하는 준비 코드이며 실제 Chromebook 캡처 지원이나 운영 승인을 뜻하지 않는다.

- 사용자 승인 범위는 실제 학생 화면이 아닌 애니메이션을 직접 생성하는 시험이다. `getDisplayMedia`·`desktopCapture`·카메라·마이크는 사용하지 않는다. 기기 확장 권한/지원 상태도 바뀌지 않는다.
- 비운영·HTTP loopback에서 `CLARIO_SYNTHETIC_MEDIA=true`를 명시해야 한다. 승인 학생·활성 수업에서 학생이 시작하며, PNG 송신/확대와 별개로 무음 WebM/VP8 녹화·순차 업로드·교사 재생을 확인한다. 이름/학번을 애니메이션에 그리지 않는다.
- 약 1초 송신/2초 교사 조회·4초 프레임 만료·10초 무송신 실패, 개별 60초/8 MiB·전역 4개·업로드 무진행 120초는 로컬 기술 한도다. 실제 수업 규모/성능/보관 정책의 합격 기준이 아니다.
- 메모리 한정·공개 URL 없음·현재 교실 관리자/송신 자격 재검사·중단/삭제·권한/수업 종료 정리를 시험한다. 시작/중단/저장/실패/삭제·교사 파일 열람 메타데이터만 기존 DB에 감사한다. 미디어 파일/백업이나 승인된 학교 보관 정책을 만들지 않는다.
- MIME 지원 응답과 파일 헤더만으로 재생 성공을 선언하지 않는다. 브라우저의 실제 디코딩·재생 시각 증가를 확인한다. 일부 내장 브라우저에서 실제 디코더가 실패하면 오류를 표시하며, 지원되는 Chrome 검증을 해당 내장 브라우저 지원으로 확대하지 않는다.

### 공식 근거와 미결정 사항

확인일 2026-10-18. 공식 API의 후보 조건은 CLARIO 또는 해당 학교에서 실행했다는 증거가 아니다. W3C 문서는 작업 초안이며 브라우저 실제 구현/학교 정책을 별도 확인한다.

- [S1: MDN getDisplayMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia) — 보안 컨텍스트·사용자 동작·매번 허용. 페이지 본문 추출 제한 시 [MDN 원문](https://raw.githubusercontent.com/mdn/content/main/files/en-us/web/api/mediadevices/getdisplaymedia/index.md) 확인.
- [S2: W3C Screen Capture 작업 초안](https://www.w3.org/TR/screen-capture/) — 선택·권한·개인정보 표시와 보안 조건.
- [S3: Chrome desktopCapture](https://developer.chrome.com/docs/extensions/reference/api/desktopCapture) — 선택 UI·취소·단기/일회 stream ID.
- [S4: Chrome alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms) — 절전에서 기기를 깨우지 않음·누락 alarm/재시작·버전별 persistence 차이. Chrome 150 전후 옵션을 최소 버전 120에 무조건 적용하지 않는다.
- [S5: Chrome enterprise.platformKeys](https://developer.chrome.com/docs/extensions/reference/api/enterprise/platformKeys)·[deviceAttributes](https://developer.chrome.com/docs/extensions/reference/api/enterprise/deviceAttributes) — 관리/affiliation·정책/권한/서버 검증 필요. 일련번호 자체는 인증이 아니다.
- [S6: MDN MediaRecorder.isTypeSupported](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static)·[MDN 원문](https://raw.githubusercontent.com/mdn/content/main/files/en-us/web/api/mediarecorder/istypesupported_static/index.md) — 포맷 지원과 자원 부족 실패 구분.

남은 결정: 학교 시험 OU/배포·정확한 기기/브라우저 버전·원본/프록시·공유 기기 정책·학교 측 비식별 시험 결과, 화면 시험 승인·성능 임계값/전송 방식, 녹화 필요성/근거/보관 상한·저장/복제/백업 삭제 구조. 이 정보가 없으면 9A 실기기 통과·9B/9C 활성화를 선언하지 않는다.
