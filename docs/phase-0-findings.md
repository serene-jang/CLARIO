# CLARIO Phase 0 조사 결과

- 조사일: 2026-10-18
- 범위: 저장소/문서 인벤토리 및 공개 기술 문서 조사
- 주의: 실제 학교 계정, 관리 콘솔, Chromebook, 학생 기기, 캡처 클라이언트 또는 운영 스토리지에 접근하지 않았다. 따라서 실기기 호환성, 실제 인증, 녹화 및 부하 성능은 검증하지 않았다.

## 1. 현재 프로젝트 상태

### 확인된 파일 및 구조

작업 시점 루트에는 다음 파일만 있었다.

- `PRD.md`
- `AGENT.md`
- `ARCHITECTURE.md`
- `TASK.md` (Phase 0 정리 후 요청된 이름인 `TASKS.md`로 통일)

소스 코드, 애플리케이션 폴더, 테스트, 문서 폴더, 패키지 매니페스트, 빌드 설정, 실행 스크립트, `.env` 또는 `.env.example`은 확인되지 않았다. Git 저장소도 아니다.

### 구현·재사용 코드

실행 가능한 기존 기능이나 소스 코드가 없어 재사용할 코드가 확인되지 않았다. PRD, 아키텍처 및 에이전트 지침은 요구사항·설계 참고 자료로 사용할 수 있다.

### 실행, 환경 변수 및 오류

- 현재 실행하거나 빌드할 앱이 없어 개발 서버, 빌드, 테스트 명령을 확인할 수 없다.
- 매니페스트와 환경 설정 파일이 없어 필요한 환경 변수는 아직 정의되지 않았다.
- 애플리케이션 실행 중 발생하는 오류는 조사할 수 없다. 프로젝트 코드가 없어 런타임 오류를 관찰하지 못했다.
- Phase 1 개발 환경 구축은 이번 작업 범위에서 시작하지 않았다.

## 2. 기기 및 운영체제 범위

대상 기기/OS의 우선순위는 확정되지 않았다. `ARCHITECTURE.md`는 Chromebook, Windows/macOS, iPad/Android를 검토 후보로 나열하지만, 실제 지원 대상으로 확정하거나 비교 검증한 결과는 아니다.

**따라서 우선 지원 기기는 미결정이다.** 실기기 테스트를 시작하려면 학교에서 사용할 기기 모델, OS/버전, 학교 관리 방식 및 보유 테스트 기기를 먼저 정해야 한다.

## 3. 학교 계정 로그인 조사

Google 계정 연동의 공개 문서상 기본 조건은 다음과 같다.

- Google Cloud 프로젝트와 OAuth 클라이언트 자격 증명
- 애플리케이션의 정확한 리디렉션 URI 등록
- OAuth 동의/브랜딩과 필요한 최소 범위(scope) 설정
- 서버에서 OIDC ID 토큰을 검증하고, 로그인 상태를 안전하게 유지
- Workspace 관리자가 조직/OU 단위로 앱 접근과 OAuth 범위를 검토 또는 제한할 수 있음

이는 가능한 연동 경로에 관한 문헌 조사다. CLARIO용 OAuth 프로젝트, 학교 도메인, 관리자 허용 목록, 정책, 테스트 계정이 제공되지 않아 로그인 연동은 구성하거나 시험하지 않았다. Google 로그인만으로 학교·학급의 교사/학생 역할이 자동으로 결정된다고 가정할 수 없다. 인증 후 서버의 권한 부여와 학급 등록 절차가 별도로 필요하다.

참고:

- [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect)
- [Google OAuth 2.0 for Web Server Applications](https://developers.google.com/identity/protocols/oauth2/web-server)
- [Control which apps access Google Workspace data](https://knowledge.workspace.google.com/admin/apps/control-which-apps-access-google-workspace-data)

## 4. Chromebook 화면 확인 기술 검토

### 확인한 공개 기능

- Chrome의 `getDisplayMedia()` 화면 공유/녹화 흐름은 캡처할 탭·창·화면을 사용자가 선택하는 브라우저 UI를 표시한다.
- Chrome 확장 프로그램의 `desktopCapture`도 화면·창·탭 선택 UI를 표시한다.
- `tabCapture`는 확장 프로그램을 사용자가 호출한 뒤 탭 미디어를 캡처하는 용도로 문서화되어 있다. 이는 학생 기기 전체 화면을 교사가 원격에서 무인 캡처하게 하는 일반 웹 API가 아니다.
- Google Class Tools 교사용 문서는 관리되는 ChromeOS에서 세션/학습자료 기능을 설명한다. ChromeOS 137 이상 및 학교 Workspace 계정 등록 조건을 명시하고, 화면 공유와 주석은 ChromeOS 144 이상으로 설명한다. 세션당 최대 학생 수 50명도 안내한다. 문서에 설명된 교실 디스플레이 공유·주석 기능은 CLARIO가 호출할 수 있는 범용 화면 모니터링 API를 뜻하지 않으며, CLARIO가 각 학생 화면을 지속적으로 열람할 수 있음을 입증하지 않는다.

### 결론

- 일반 교사 웹 앱만으로 다른 학생 기기의 화면을 몰래 또는 원격으로 가져오는 방법은 확인되지 않았다.
- 표준 브라우저 캡처 API는 사용자 선택/호출을 전제로 하며, 학생 기기의 화면을 교사 웹 앱에 자동으로 공급하지 않는다.
- 관리된 Chromebook에서 가능한 실제 접근 방식은 해당 학교의 ChromeOS 정책, 기기 및 계정 조건, 공식 Class Tools의 기능 범위, 또는 별도 승인된 관리형 클라이언트/확장 프로그램 제공 여부에 달려 있다.
- **CLARIO의 Chromebook 학생 화면 실시간 확인은 미검증이며 지원한다고 선언할 수 없다.** 대상 학교의 관리형 기기와 정책으로 실기기 검증이 필요하다.

참고:

- [Chrome: Audio recording and screen capture](https://developer.chrome.com/docs/extensions/how-to/web-platform/screen-capture)
- [Chrome Extensions: desktopCapture API](https://developer.chrome.com/docs/extensions/reference/api/desktopCapture)
- [Chrome Extensions: tabCapture API](https://developer.chrome.com/docs/extensions/reference/api/tabCapture)
- [Google ChromeOS Class Tools — Use Class Tools](https://support.google.com/chrome/a/answer/16058637?hl=en)

## 5. 여러 학생 화면 녹화 및 저장

### 문헌 조사로 판단 가능한 범위

화면 녹화는 캡처 가능한 스트림이 존재하고 적절한 사용자 선택/권한을 얻은 뒤 그 스트림을 녹화·전송·저장하는 방식으로는 구현할 수 있다. 다만 브라우저 화면 캡처 API가 학교의 모든 학생 기기 스트림을 교사 앱에 제공하는 것은 아니다.

여러 학생의 화면을 녹화하려면 최소한 다음을 각 대상 기기에 대해 검증해야 한다.

- 승인된 화면 캡처 주체(기기 클라이언트/관리형 확장 프로그램 등)와 해당 OS의 허용 범위
- 학생에게 필요한 사전 안내, 권한 및 학교 정책 승인
- 학생별 스트림의 연결·인코딩·업로드, 재연결 및 미녹화 구간 처리
- 동시 스트림 수에 따른 학생·교사 네트워크 대역폭, 서버 처리량과 저장 용량
- 학교별 접근 통제, 암호화, 만료와 원본·복제본 삭제

### 결론

- **학생 여러 명의 실제 화면을 CLARIO가 동시에 녹화할 수 있는지 확인되지 않았다.**
- Class Tools의 최대 50명 세션 조건은 Class Tools 세션 수용 인원이며, CLARIO의 동시 녹화 수나 영상 저장 성능을 보장하지 않는다.
- 여러 화면을 하나의 영상으로 합치거나, 별도 파일로 저장하는 방식 모두 대상 장치의 캡처 스트림이 승인된 방법으로 제공되는지 먼저 확인해야 한다.
- 실기기/클라이언트와 네트워크·저장소 부하 시험 전에는 동시 녹화 수, 화질, 업로드 신뢰성 또는 보관/삭제 성능을 보장할 수 없다.

## 6. 일반 웹 기능과 별도 환경이 필요한 기능

| 기능 | 일반 웹에서 가능한 범위 | 별도 검증/환경 필요 |
|---|---|---|
| 계정 로그인 | OAuth/OIDC 공급자가 설정되고 서버 검증이 구현되면 웹 로그인 가능 | 학교 Workspace 설정, OAuth 자격 증명, 관리자 앱 접근 정책, 학교/학급 권한 매핑 |
| 수업 링크 전달 | 인증된 API와 실시간 연결을 통해 웹 앱 간 전달 가능 | 학생 클라이언트/브라우저가 실행 중이거나 오프라인 전달 큐가 필요 |
| 연결 상태 표시 | Student Client가 온라인 상태 이벤트를 보내는 범위에서 가능 | 기기 등록과 학생 클라이언트가 필요하며, 브라우저가 닫힌 동안 상태의 정확도는 검증 필요 |
| 화면 공유/캡처 | 사용자가 직접 선택·호출한 해당 브라우저의 탭/창/화면 캡처 | 학생 기기 원격 확인, 무인 캡처, OS 전체 제어는 별도 관리형 클라이언트/정책 검증 필요 |
| 집중 모드/기기 제어 | CLARIO 웹 앱 안의 자료·내비게이션 경험 일부 제어 | 브라우저 밖 앱/웹 차단 및 관리 정책 적용은 OS·MDM/Chrome 관리 설정 필요 |
| 여러 학생 녹화 | 제공된 캡처 스트림을 처리하는 앱 구조는 설계 가능 | 모든 학생 기기의 승인된 스트림 공급, 녹화 권한, 동시성/저장 용량 시험이 선행되어야 함 |

## 7. 문제, 제한 및 필요한 준비물

### 발견된 프로젝트 문제

- 코드/매니페스트/테스트/실행 설정 부재로 기존 기능, 기술 스택, 실행 방법 및 런타임 오류를 확인할 수 없다.
- 이전 파일명이 `TASK.md`였으나 요청 및 에이전트 지침은 `TASKS.md`를 참조했다. 이제 `TASKS.md`로 이름을 통일했다.
- 현재 Phase 0 조사만 수행했으며 Phase 1 개발은 시작하지 않았다.

### 다음 기술 검증에 필요한 것

1. 우선 지원 OS·기기 모델·OS/ChromeOS 버전과 학교 내 관리 방식
2. 실기기 테스트가 가능한 학교 소유 Chromebook 및 교사 계정/학생 테스트 계정
3. Google Workspace for Education 테넌트와 관리 콘솔 담당자의 협조 및 Class Tools/앱 정책 확인
4. 로그인 방식 확정, OAuth 개발용 프로젝트·클라이언트·리디렉션 URI 및 필요한 도메인/관리자 허용 설정
5. Class Tools만 사용할지, CLARIO가 별도 관리형 클라이언트/확장 프로그램을 제공할지에 대한 결정
6. 학생 안내·동의/승인, 녹화 허용 조건, 학교별 보관 기간 및 관련 법무/개인정보 담당자 검토
7. 동시 대상 학생 수, 목표 화질/프레임률, 수업 길이, 업로드 대역폭과 저장 용량 요구사항

## 8. Phase 0 체크 결과

프로젝트 인벤토리와 네 문서 검토, 기존 코드/설정 부재 확인, Google OIDC와 Workspace 앱 접근 관리의 문헌 조사는 완료했다. 화면 캡처 API의 제한과 Google Class Tools의 문서상 요건도 조사해 기록했다.

**Phase 0 전체 완료 여부: 미완료.** 대상 기기/학교 관리 환경이 정해지지 않았고, 실기기에서 Chromebook 화면 확인, 승인된 클라이언트 필요 여부, 다중 학생 녹화·업로드·저장 동시성 및 삭제 정책을 검증하지 못했다. `TASKS.md`에서 해당 항목은 완료 처리하지 않았다.

다음 순서는 실제 대상 기기와 학교 관리 환경을 확정하고 시험용 계정/기기를 준비한 뒤 Phase 0.2의 미완료 기술 검증을 수행하는 것이다. 이를 완료하기 전에는 화면 확인과 녹화 구현을 지원 기능으로 취급하지 않는다.
