# CLARIO

## 첫 실행 가능한 웹 MVP — 현재 실행 경로

**학교 API·Google OAuth·Drive 설정 없이** 교사 이메일 가입 → 교실/초대코드 →
학생 무계정 신청/교사 승인 → 학생 검색/관리 → 전체/선택 URL 배포 → 집중 안내와
교사 전용 알림을 사용합니다. 교사는 선택적으로 CLARIO 브라우저 탭을 직접 녹화해
같은 브라우저에 보관할 수 있습니다. 아래의 이전 단계/Google/확장/미디어 설명은 기존 코드
기록이며 현재 MVP의 기능 목록이나 필수 설정이 아닙니다..

### 빠른 실행 (로컬 개발)

Node.js 24 LTS와 npm을 준비한 뒤 프로젝트 루트에서 실행합니다.

```powershell
npm ci
npm run mvp
```

처음 실행은 PostgreSQL 초기화와 빌드 때문에 시간이 걸릴 수 있습니다.
실행된 터미널을 유지하고 다음 주소를 엽니다.

- 교사: http://127.0.0.1:4000/teacher/
- 학생: http://127.0.0.1:4000/student/
- 준비 상태: http://127.0.0.1:4000/ready

교사/학생은 **서로 다른 브라우저 또는 프로필**을 사용합니다. 여러 학생은 각자 다른
프로필/브라우저를 사용하세요. 같은 프로필의 여러 탭은 같은 학생 쿠키를 공유합니다.
교사는 이메일 회원가입으로 표시 이름·이메일·12~128자 비밀번호를 등록합니다.
학교 API나 관리자 계정은 입력하지 않습니다.

1. **교실 만들기** 후 표시되는 12자 초대코드를 학생에게 전달합니다.
   원문은 발급 때만 보이므로 잃어버리면 **코드 재발급**을 사용합니다.
2. 학생은 초대코드·이름·학번(예: `001`)으로 신청합니다. 이름/학번만으로 본인 인증되지는 않습니다.
3. 교사 화면은 신청을 5초마다 확인합니다. **참여 승인** → 본인 확인란 → **확인하고 승인**을 누릅니다.
4. 학생은 **다시 확인** → **승인된 수업 연결 확인**을 누릅니다.
   승인된 학생이 교사 **참여 학생 관리**에 표시되고 서버 검색·정렬·퇴장/참여 차단이 가능합니다.
   참여 차단은 웹 참여 자격 철회이지 기기/OS 제어가 아닙니다.
5. 수업 자료 제목·HTTPS URL·**배포 대상**(학급 전체/선택한 학생)을 정하고 **자료 등록**합니다.
   전체 자료는 이후 승인된 학생도 볼 수 있고 선택 자료는 당시 선택한 참여자만 볼 수 있습니다.
   학생 목록은 10초 이내 다음 조회에서 갱신됩니다. 수신/열기는 읽기 완료를 뜻하지 않습니다.
6. **수업 시작** 후 자율 집중 안내를 켜면 교사/학생 화면에 서버 상태가 반영됩니다.
   브라우저/앱을 잠그거나 입력/화면을 감시하지 않습니다.
7. **교사 전용 알림**은 실제 신청·승인·자료·집중 처리 기록과
   **테스트 · 실제 감지 아님** 이벤트를 분리합니다. 테스트 생성 버튼은 화면 비교/입력 감지를 실행하지 않습니다.
8. 수업 시작 후 교실 관리의 **교사 대시보드 녹화**는 교사가 시작을 누르고 브라우저 화면 선택창에서
   CLARIO 탭을 선택해야 작동합니다. 녹화 데이터는 그 브라우저의 IndexedDB에 보관되며
   재생·다운로드·수동 삭제가 가능합니다. 마이크/시스템 오디오나 학생 기기 화면을 수집하지 않습니다.
   수업을 종료하면 녹화를 마무리합니다.
   브라우저 데이터 삭제·저장 공간 부족·기기 고장으로 파일이 사라질 수 있으므로 필요한 파일은
   별도 다운로드해 보관하세요. Google Drive 업로드는 아직 제공하지 않습니다.
   브라우저 IndexedDB의 저장 암호화를 CLARIO가 보장하지 않으므로 민감한 기록은 공용 기기에 남기지 마세요.

데이터는 `server/.local-postgres`의 PostgreSQL에 저장되며 새로고침·정상 종료/재시작 후 유지됩니다.
교사 로그인 토큰은 메모리 전용이므로 **새로고침 후 재로그인**하면 기존 교실을 다시 조회합니다.
학생은 유효 HttpOnly 쿠키로 복원됩니다. 참여 쿠키 만료/삭제 시 교사 확인을 통한 복구가 필요합니다.
`Ctrl+C`는 서비스를 종료하지만 DB를 삭제하지 않습니다. 연결 파일에는 개발 DB 비밀번호가 있으므로
공유하거나 Git에 추가하지 마세요. 로컬 데이터가 필요하면 해당 폴더를 임의로 삭제하지 마세요.

### 환경 변수와 실행 제한

| 변수 | 로컬 MVP | 일반 서버 (`npm start`) |
|---|---|---|
| `CLARIO_MVP_PORT` | 선택, 기본 `4000` | 미사용 (`PORT` 사용) |
| `CLARIO_MVP_DATA_DIR` | 선택, 개발 DB 전용 절대 경로. 기본 `server/.local-postgres` | 미사용 |
| `DATABASE_URL` | launcher가 자체 loopback DB 연결 생성, 기존 설정을 사용/변경하지 않음 | 필수, PostgreSQL 연결 문자열 |
| `APP_ORIGINS` | `http://127.0.0.1:<포트>`로 고정 | 필수, 허용되는 정확한 웹 원본들을 쉼표로 구분 |
| `SERVE_WEB` | 두 빌드를 같은 서버에서 제공 | `true`면 `/teacher/`·`/student/` 정적 빌드 제공 |
| `PORT` | 미사용 | 기본 `4000` |
| `NODE_ENV` | 비운영 전용, `production`이면 실행 거부 | 운영은 `production`과 HTTPS/신뢰 프록시 필요 |
| `GOOGLE_CLIENT_ID` | 사용하지 않음 | 기존 호환 Google 어댑터용 선택값. 현재 교사 MVP UI는 외부 로그인 비활성 |

포트가 사용 중이면 `$env:CLARIO_MVP_PORT='4010'; npm run mvp`로 바꿉니다.
DB 포트 `55432`를 이미 다른 PostgreSQL이 사용하면 기존 프로세스를 임의 종료하지 말고
별도 환경으로 실행하거나 일반 서버 연결 설정을 사용하세요.
로컬 launcher는 본인이 관리하는 개발 DB만 스키마 **14**로 마이그레이션합니다.
운영 DB는 백업/승인 후 `npm run db:migrate --workspace @clario/server`를 명시적으로 실행해야 합니다.
일반 서버 설정은 `.env.example`을 참고해 `server/.env`에 두고 `npm run build` → `npm start`합니다.

다른 브라우저 연결은 같은 중앙 Express/PostgreSQL을 이용하며 localStorage로 흉내 내지 않습니다.
로컬 launcher는 **127.0.0.1 전용**입니다. 다른 컴퓨터/학교 기기로 배포하려면 중앙 호스팅,
동일 원본 HTTPS·프록시 Host/쿠키·DB 영속성/백업을 별도로 구성해야 합니다.
이번 작업은 Azure 공개 배포나 실제 학생 기기 연결/운영 검증을 포함하지 않습니다.

### 이번 MVP에서 제공하지 않는 기능

- 실제 학생 화면 캡처·화면 비교·키보드/마우스 입력 감지, Google Drive 녹화 업로드
- 외부 로그인 API, 강제 사이트/앱 차단·기기 잠금, 확장 강제 설치
- 이메일 소유 확인·비밀번호 재설정, 학교/교사 신분 검증, 운영 보관/백업 자동 삭제

교사 탭 녹화는 별도 브라우저 기능이며 서버 업로드·Drive 연동과는 연결되지 않습니다.
미래 Drive 경계와 후속 작업은
[ARCHITECTURE.md](./ARCHITECTURE.md#현재-mvp-실행-경계)와
[TASKS.md](./TASKS.md#후속-작업--이번-mvp에서-구현하지-않음)에 있습니다.
기능 확장은 승인/권한·학생 고지·저장/접근·삭제 검증 후 진행해야 합니다.

## 이전 단계의 개발 기록 (현재 MVP 범위는 위 절 우선)

CLARIO는 **누구나 Google 계정 또는 이메일·비밀번호로 가입해 본인 교실을 만들고, 학생은 로그인 없이 초대코드·이름·학번으로 신청해 교사 승인 후 참여하는 중앙 서버 기반 서비스**를 개발하는 프로젝트입니다. 학교 API 연동·학교 이메일·학교 관리자 사전 등록은 일반 가입의 필수 조건이 아닙니다.

### 공개 교사 가입

- 교사 앱의 기본 진입 화면은 실제 **가입·로그인**입니다. Google 계정이 없어도 **이메일 회원가입**에서 표시 이름·이메일·12~128자 비밀번호를 입력해 가입합니다. 재로그인은 **이메일 로그인**을 사용합니다.
- 서버 운영자가 `DATABASE_URL`과 `APP_ORIGINS`를 설정하고 스키마 **13**으로 마이그레이션하면 이메일 가입이 동작합니다. `GOOGLE_CLIENT_ID`는 선택 사항이며 설정하면 개인/Workspace Google 가입도 추가됩니다. 가입자가 학교 API나 OAuth 설정을 입력하지 않습니다.
- 비밀번호는 임의 salt를 붙인 scrypt 해시만 저장합니다. 세션은 기존 1시간·DB 토큰 해시·UI 메모리 보관 방식을 사용합니다. 가입은 학교 소속이나 교사 자격의 증명이 아니며 기존 학교 관리자 권한이나 다른 교실 접근을 부여하지 않습니다.
- **이메일 소유 확인·비밀번호 재설정·로그인 방식 간 계정 연결은 아직 제공하지 않습니다.** 이메일 계정과 Google 계정을 같은 이메일만으로 자동 합치지 않습니다. 기존 계정이 있으면 원래 가입한 방식으로 로그인해야 합니다. 이메일 기반 권한 초대/학교 소속 검증에 미확인 이메일을 사용하면 안 됩니다.
- PostgreSQL에 이메일/IP별 가입·로그인 시도 횟수를 공유합니다. 15분 창 기준 이메일 10회·소켓 IP 40회이며 프로세스당 scrypt는 최대 4개입니다. 프록시 전달 IP를 임의 신뢰하지 않으므로 공개 운영 전 실제 프록시와 공유 IP 용량을 확인해야 합니다.
- **현재 공개 미리보기에는 이 변경을 아직 배포하거나 DB를 구성하지 않았습니다.** 코드 구현과 실제 서비스 개통은 별개이며 UI만 재배포해도 계정 저장은 활성화되지 않습니다.

**8단계 자율 집중 안내까지 구현했습니다.** 학생은 Google 로그인 없이 코드·이름·학번으로 신청하고 교사 승인 뒤 본인 쿠키로 참여합니다. 수업 중 학생 10초 heartbeat·교사 5초 HTTPS 조회로 현황을 갱신하며 20초 미만 온라인·20~45초 재연결·45초 이상 오프라인을 판정합니다. 서버 조회 실패는 확인 불가입니다. 다중 탭도 학생 한 명으로 집계하고 수업 종료 후 유효 자격은 다음 수업에 코드 없이 재접속합니다. 자료는 교사 등록/삭제와 학생 자동 목록·수신/열기 요청을 지원합니다. 자율 집중 안내는 현재 수업/버전을 검증해 변경하며 학생에게 10초마다 상태를 표시합니다. 수업/교실 종료 시 해제되고 다음 수업은 꺼짐입니다. 강제 차단이나 학생 행동 수집은 하지 않습니다. 참여 학생 관리·신청 목록은 별도 수동 조회이며 승인 자체는 온라인이 아닙니다. 실제 OAuth·운영 DB/같은 원본 HTTPS·프록시/IP 검증은 남아 있습니다.

기존 작업공간 가입·명부·기기 기능은 별도 로그인으로 유지합니다. 이메일 도메인만으로 학교 소속을 검증하지 않습니다. 기존 **기기 페어링 코드**는 **교실 초대코드**, 승인 학생의 **확장 연결 코드**와 다릅니다. 후속으로 비공개 PDF 공유와 연결된 Chrome 프로필의 도메인 차단을 추가했습니다. 강제 설치·OS 앱 제어·실제 학생 화면 확인/녹화는 제공하지 않습니다. 합성 애니메이션의 로컬 공유·녹화·교사 재생 시험은 실제 화면과 분리합니다.

**9단계는 검증 준비를 진행했습니다.** 관리형 Chromebook/관리자 협조 가능은 확인했으나 실기기 시험 결과는 없고 화면·녹화 승인도 아직 없습니다. 로컬 권한/자격 분리·worker 수명주기 대역 회귀를 보강하고 [관리자용 수집 없는 시험 절차·결과표](./docs/device-client.md#9단계-검증-준비--수집-없는-학교-시험)를 준비했습니다. 9단계 전체 통과나 화면·녹화 구현 완료를 의미하지 않습니다.

**10·11단계는 로컬 통합·운영 준비 범위입니다.** 학생별 명시적 삭제 요청은 접근 철회·복구 보류 후 **정책 승인 대기**로 저장하며 원본/백업은 삭제하지 않습니다. 버전 11과 선택형 `SERVE_WEB=true`로 `/teacher/`·`/student/`·`/api`를 같은 중앙 서버에서 제공하고 `/ready`로 설정·DB 스키마를 `/health`와 구분합니다. CI에 두 웹 빌드와 runtime 검증을 포함하며 실제 배포는 기본 차단합니다. 실제 OAuth·학교 보관/삭제 정책·운영 HTTPS·백업/복구·부하·배포는 별도 승인/검증이 필요합니다. [현재 실행·개인정보·출시 게이트](./docs/azure-deployment.md#현재-1011단계--로컬-운영-준비)를 참고하세요.

### PDF 공유와 수업 사이트 차단

현재 시작 스키마는 **14**입니다. 기존 DB 백업/중단 절차를 확인한 뒤 `npm run db:migrate --workspace @clario/server`를 명시적으로 실행합니다. 운영 DB나 기존 공개 배포를 이번에 변경하지 않았습니다.

- **PDF 공유:** 서버의 `CLARIO_DOCUMENTS_DIR`를 저장소/공개 웹 루트 밖의 전용 절대 경로로 설정합니다. 미설정은 비활성입니다. 교사 로그인→교실 관리→**PDF 문서 열기**에서 제목과 PDF를 업로드하고, 승인 학생은 같은 메뉴에서 다운로드합니다. PDF 1.x/2.0 헤더·종료 표식만 검사하며 **악성코드 검사나 완전한 PDF 유효성 검사는 없습니다.** 파일당 최대 10 MiB·교실당 최대 100개입니다. 신뢰할 수 있는 문서의 승인된 시험용이며 운영 악성 파일 검사는 별도입니다.
- 파일은 공개 URL이 아닌 서버 디스크에 있고 다운로드마다 현재 교실 권한을 검사합니다. 응답은 첨부파일/no-store이며 접근·삭제를 파일 ID와 함께 감사합니다. 관리 교사의 원본 삭제는 실제 파일 제거 후 완료됩니다. 실패는 삭제 대기/재시도로 표시합니다. 업로드 미완료/실패도 교사가 삭제 후 재등록할 수 있습니다. 다운로드된 사본 회수·자동 만료·백업/복제본 삭제는 제공하지 않습니다. 운영 전 저장소 암호화·영속 볼륨/권한·학교 보관 정책·백업을 검증해야 합니다.
- **사이트 차단:** 교사는 교실의 **사이트 차단 설정 열기**에서 도메인 최대 50개를 저장합니다. 활성 수업에만 도메인과 하위 도메인의 새 페이지/프레임 요청을 차단합니다. 학생은 승인된 학생 웹에서 5분·일회용 **확장 연결 코드**를 발급하고 확장 팝업의 학생 웹 코드 항목으로 연결합니다. 초대코드나 Google 로그인은 확장 자격이 아닙니다.
- 설치·연결된 해당 Chrome 프로필에만 적용됩니다. 확장은 약 30초마다 갱신하며 실패·자격 철회·수업 종료 후 동기화 또는 최대 60초 서버 정책 만료 시 규칙을 해제합니다. 절전/브라우저 alarm 지연 시 해제도 지연될 수 있어 정확한 벽시계 상한을 보장하지 않습니다. 기존 페이지 내용·다른 프로필/브라우저·OS 앱·기기 잠금은 제어하지 않습니다. 확장 강제 설치/삭제 방지는 학교 관리자가 별도로 수행해야 합니다.

설치·API·정확한 제한은 [Device Client 안내](./docs/device-client.md), 디스크/운영 승인 절차는 [운영 안내](./docs/azure-deployment.md)를 참고하세요. 서버 정책이나 확장 마지막 접속을 실제 차단 성공/학생 준수의 증거로 표시하지 않습니다.

### 실제 화면 코드의 현재 상태

후속 요청에 따라 브라우저 화면 선택·무음 녹화·중단/권한 상실 정리 엔진 코드를 준비했습니다. **실제 화면 수집은 여전히 비활성**이며 시작 버튼도 잠겨 있습니다. 학생의 `실제 녹화 정책 확인`은 서버의 차단 사유만 확인합니다. 정책 승인·보관 기간/상한·저장소·교사 열람·복제/백업 삭제가 연결되지 않아 시작/업로드 API는 403입니다. 클라이언트 승인 필드나 합성 시험 설정으로 해제할 수 없습니다. 엔진은 대역 테스트만 수행했으며 실제 화면 선택 창·학생 수집·교사 실제 화면 전달·수업 후 영구 저장은 아직 검증/구현 완료가 아닙니다.

### 합성 화면 로컬 시험

학교의 실제 화면/녹화 승인이 없어 **생성 canvas만** 사용합니다. Google/DB를 구성한 로컬 서버에서 `NODE_ENV=development`, `SERVE_WEB=true`, `CLARIO_SYNTHETIC_MEDIA=true`, 해당 서버의 HTTP loopback `APP_ORIGINS`를 설정하고 `npm run build` 후 `npm start`로 실행합니다. 기본값은 `false`이며 운영/비로컬 원본에서는 활성화를 거부합니다. 예를 들어 기본 포트면 원본은 `http://127.0.0.1:4000`이고 웹은 `/teacher/`, `/student/`입니다. 실제 OAuth 우회 기능은 없습니다.

교사는 로그인→교실 관리→학생 승인→수업 시작→**교사 합성 미디어 시험 열기**, 학생은 승인된 교실에서 **합성 미디어 시험 확인→합성 화면 공유·녹화 시작**을 누릅니다. 프레임 확대·중단 후 완료된 WebM 재생·명시적 시험 삭제를 지원합니다. 4초 이상 프레임은 숨기고 지원/인코딩/업로드/재생 오류를 표시합니다. 최대 4개·개별 60초/8 MiB는 기술 한도입니다. 파일은 서버 메모리에만 있고 디스크·복제/백업은 만들지 않습니다. 수업/자격 종료·시험 삭제·서버 종료 시 정리하며 감사 메타데이터는 DB에 남습니다. 실제 화면 선택, 자동 학생 녹화, 운영 보관/자동 삭제는 아직 제공하지 않습니다.

2026-10-18 새 흐름 개발의 0단계 기준선 검증에서 기존 앱 테스트 71개와 배포 검증 테스트 2개, 포맷·타입·전체 빌드가 통과했습니다. 임시 포트에서 빌드 API의 `/health` 200과 미설정 인증 API의 명시적 503도 확인했습니다. 이는 실제 Google 로그인·학생 코드 참여·실기기 검증 완료를 의미하지 않습니다.

후속 1단계에서 앱 테스트 110개와 배포 검증 2개·타입·빌드·포맷이 통과했습니다. 실제 임시 PostgreSQL의 전환/rollback·교실 격리·학번/정원 경합·자격 저장 제약을 포함하며 새 학생 HTTP/쿠키 검증 완료는 아닙니다.

2단계에서는 앱 테스트 131개·배포 검증 2개를 통과했습니다. 실제 학생 Vite 프록시·임시 PostgreSQL의 쿠키/만료/회전/종료·감사 실패 rollback을 포함합니다. 브라우저에서도 대기 복원·합성 승인 후 활성화·새로고침·종료와 DB/감사 반영·만료 오류를 확인했습니다. 공개 신청/교사 승인 UI·실제 교사 OAuth·운영 프록시 검증은 남아 있습니다.

학교 관리형 Chromebook의 **학생 웹 방문 없는 자동 연결**에 관한 조사와 조건은 [Chromebook Phase 0 문서](./docs/chromebook-phase-0.md)에 있습니다. 후속으로 일회성 코드 페어링·30초 상태 전송·학급 링크 전달 코드를 추가했습니다. [Device Client 설정과 제한](./docs/device-client.md)을 참고하세요. 기기 관리·학교 확장 배포 권한·실기기 연결·화면 캡처는 미검증입니다.

## 설치 및 실행

### 로그인 없이 화면 먼저 보기

교사 앱의 가입·로그인 화면에서 **로그인 없이 데모 체험**을 선택하면 서버 없이 **대시보드 미리보기**를 엽니다. Google 설정이나 API 연결 없이 학급 선택, 예시 기기 검색/상태 필터/상세, 자료 준비·삭제, 자율 집중 안내, 녹화 미제공 안내, 작업공간 이름 변경 화면을 확인합니다. 학생 앱은 실제 신청 화면의 **서버 없이 학생 데모 보기**에서 예시 참여/승인 흐름을 확인할 수 있습니다. 모든 데모 데이터는 예시이며 브라우저 메모리에서만 동작하고 새로고침하면 초기화됩니다. 데모 자체는 서버 요청·실제 기기 제어·녹화를 하지 않습니다.

실제 교사 계정 등록/로그인에는 중앙 CLARIO 서버와 DB가 필요합니다. Google 인증은 Google 로그인에만 필요하며 이메일 가입에는 필요하지 않습니다. 별도의 **학교 API/Workspace 관리자 사전 등록은 필수 조건이 아닙니다.** 데모 버튼은 이 보안 경계를 우회하거나 가짜 로그인하지 않습니다. **기존 작업공간 로그인·계정 연결**은 별도 기존 서비스 경로입니다. 학생 웹은 로그인 없이 본인 상태를 조회하고 코드·이름·학번으로 신청합니다. API 미설정이면 입력 성공 대신 명시적 오류를 표시합니다.

### 인증 후 교실·초대코드 관리

교사 Google 또는 이메일 로그인 후 **교실 만들기**에서 이름·정원(기본 40/최대 100)을 입력합니다. 서버에 교실·관리 관계·초기 초대코드를 함께 저장합니다. **관리 열기**에서 이름/정원·선택 명단의 이름/학번·초대코드를 관리합니다. 명단은 실제 참여 학생 목록이나 자동 승인 기능이 아닙니다.

코드는 12자·24시간 유효하며 생성/재발급 때만 원문을 볼 수 있습니다. 서버에는 해시만 남고 브라우저에는 영구 저장하지 않습니다. 재확인·다른 작업·숨기기·만료·로그아웃 후 원문은 다시 볼 수 없으므로 필요하면 재발급하세요. 재발급/폐기는 접수된 신청과 승인 관계를 취소하지 않습니다.

**교실 종료/보관**은 확인 후 코드·대기 신청·학생/기기 연결과 자격을 종료합니다. 기록 삭제가 아니며 현재 다시 열기는 제공하지 않습니다. 종료/보관 교실도 관리자 목록에서 다시 조회할 수 있습니다. 미리보기의 합성 학생 카드와 이 실제 교실 관리 화면은 별개입니다.

### 학생 신청·교사 승인·복구

1. 학생은 학생 웹에서 초대코드·이름·문자열 학번(예: `001`)을 입력하고 **참여 신청**합니다. 최대 30분 동안 본인 승인 대기 상태만 봅니다.
2. 교사는 해당 교실 **관리 열기 → 신청 목록 다시 확인**에서 신청과 명단 대조를 확인합니다. 명단 일치도 신원 증명이 아니므로 학생을 직접 확인한 뒤 승인 확인란과 **확인하고 승인**을 선택합니다. 거절도 가능합니다.
3. 학생은 **다시 확인 → 승인된 수업 연결 확인**으로 본인 자격을 활성화합니다. 새로고침 후에도 유효 쿠키로 복원하며 실제 수업 연결 상태·교실 자료·자율 집중 안내를 자동 조회합니다.
4. 새 기기/쿠키 분실·교사 퇴장/차단 뒤에는 **기존 참여 복구 요청**을 선택합니다. 복구 신청만으로 기존 기기를 끊지 않습니다. 교사가 본인을 확인하고 복구 승인할 때 이전 자격/연결을 철회하며 새 기기에서 활성화합니다.
5. 공유 기기 사용 후 **참여 종료 · 이 기기 정보 지우기**를 누릅니다. 거절된 신청도 종료 후 재신청합니다. 브라우저는 한 번에 한 교실만 참여합니다.

429는 재시도 안내를 따르세요. 브라우저 한도와 별도로 공유 IP·코드 한도가 있어 쿠키 삭제만으로 해결되지 않습니다. 서버는 임의 전달 IP를 신뢰하지 않으며 프록시 뒤에서는 공유 한도가 보수적으로 적용될 수 있습니다.

### 교실 자료 공유

교사의 **관리 열기 → 수업 자료 공유**에서 제목과 인증 정보 없는 HTTPS 링크를 등록합니다. 학생은 승인 후 유효 자료를 10초마다 조회하며 새로고침·재접속해도 만료 전 자료를 볼 수 있습니다. 교사는 5초마다 현재 승인 학생의 목록 수신·열기 요청 집계를 확인합니다. 양쪽 모두 최신순 50개 페이지를 제공합니다.

학생의 **자료 열기**는 그 순간 서버가 자격/교실/자료를 다시 확인합니다. 성공하면 5초 동안 **외부 자료로 이동** 링크가 나타납니다. 이 링크를 직접 눌러 새 탭으로 이동하며 시간이 지나면 다시 권한을 확인하세요. 비동기 자동 팝업은 사용하지 않습니다. 외부 사이트의 안전성·접근 권한·로딩/읽기 완료를 보장하지 않습니다. 서버 장애는 마지막 결과/확인 불가로 표시하고 열기·변경을 막습니다.

자료는 등록 후 7일간 접근 가능하며 만료는 자동 물리 삭제가 아닙니다. **자료 삭제 준비 → 확인하고 자료 삭제**는 자료와 기기/학생 수신 기록을 제거하고 감사를 남깁니다. 이미 열린 외부 사이트·복사된 주소는 회수할 수 없습니다. 수업 종료는 자료를 유지하지만 참여 종료·교실 종료·퇴장/차단·자격 만료는 학생의 새 접근을 차단합니다. 파일 업로드는 아직 지원하지 않습니다.

### 입력 화면으로 최초 로컬 설정 (권장)

```powershell
npm run setup
```

터미널에 표시된 **`#` 이후를 포함한 전체 로컬 주소**를 브라우저에서 엽니다. Google OAuth 클라이언트 ID, 작업공간 이름·관리자 이메일·이름을 입력하면 로컬 PostgreSQL 시작, DB 마이그레이션, 작업공간·관리자 등록, `server/.env` 저장을 진행합니다. DB 비밀번호나 Google Client secret을 입력하지 않습니다.

이 설정 도구는 기존 작업공간 초기화도 함께 수행합니다. **독립 교사 로그인만 사용하면 작업공간/최초 관리자 생성은 필요 없습니다.** [수동 DB·OAuth 설정](./docs/phase-2-authentication.md#로컬-postgresql-준비) 후 버전 10까지 마이그레이션을 적용하면 됩니다.

설정 터미널은 DB 실행을 위해 유지하고, 화면에 안내된 `dev:server`, `dev:teacher`, `dev:student` 명령을 각각 별도 터미널에서 실행합니다. 이미 실행 중인 API는 해당 터미널에서 재시작해야 새 설정이 적용됩니다. 이후 다시 개발할 때는 `db:local`로 DB를 시작할 수 있습니다.

이 화면은 `127.0.0.1:5180`에서만 실행하는 **로컬 전용 도구**입니다. 공개 API에 설정 경로를 추가하지 않으며 Azure 배포 설정도 바꾸지 않습니다. 터미널 주소는 설정 권한을 포함하므로 공유하지 마세요. 기존 외부 DB/비표준 포트·허용 주소는 덮어쓰지 않습니다. Google Cloud의 OAuth 클라이언트 설정은 직접 필요합니다. 학교 계정 관리 권한은 개인 작업공간 생성에 필요하지 않지만, 학교가 관리하는 Google 계정의 로그인 정책은 적용됩니다.

프로젝트 루트에서 의존성을 설치합니다.

```powershell
npm install
```

각 앱은 별도 터미널에서 실행합니다.

```powershell
npm run dev:teacher
npm run dev:student
npm run dev:server
```

개발 서버 주소:

- Teacher: http://127.0.0.1:5173
- Student: http://127.0.0.1:5174
- API health check: http://127.0.0.1:4000/health

**학생 쿠키 경로:** 학생 앱은 상대 경로 `/api/student`와 기존 Vite `/api` 프록시를 사용합니다. 학생 원본(기본 `http://127.0.0.1:5174`)을 `APP_ORIGINS`에 포함하고 프록시가 원래 Host를 보존해야 합니다. 학생에게 `VITE_API_BASE_URL`로 별도 API 사이트를 지정하지 않습니다. 운영은 HTTPS·같은 원본 API 연결이 필수이며 현재 Azure 분리 호스팅의 프록시는 별도 구성/검증이 필요합니다. 브라우저당 한 교실이며 공유 기기 사용 후 **참여 종료 · 이 기기 정보 지우기**를 누릅니다.

서버는 프로젝트 루트의 `.env.example`을 `server/.env`로 복사해 로컬 설정을 지정할 수 있습니다. npm workspace로 실행하면 서버 폴더를 기준으로 설정을 읽습니다. 로컬 API의 `PORT` 기본값은 `4000`입니다. `NODE_ENV=production`이면 `0.0.0.0`, 그 외에는 `127.0.0.1`에 바인딩합니다. `.env`는 Git에서 제외됩니다. 이메일 로그인에는 `DATABASE_URL`, `APP_ORIGINS`와 버전 13 마이그레이션이 필요합니다. Google 로그인을 함께 제공하려면 `GOOGLE_CLIENT_ID`를 추가합니다. 학교 관리자 등록은 기존 작업공간 이용에만 필요합니다. 아무 인증 설정도 없으면 `/health`는 유지하고 `/api`는 설정 미완료(503)를 반환합니다.

**로그인 개발 시작:** [인증 설정 안내](./docs/phase-2-authentication.md#공개-이메일비밀번호-가입)를 따라 DB/원본 설정·마이그레이션 후 이메일로 가입합니다. Google 로그인은 운영자가 OAuth 클라이언트를 준비한 경우에만 추가로 활성화됩니다. 학생/교사가 각자 OAuth 클라이언트를 만들거나 계정 비밀번호를 운영자에게 전달하지 않습니다. 아래 로컬 설정 마법사는 기존 Google 작업공간용이며 공개 이메일 가입에는 필요하지 않습니다.

**기존 학생 기기 등록 경로:** 기존 작업공간 로그인 후 담당 학급의 **학급 관리 → 학생 기기 등록**에서 학생·기기 이름·자산번호를 입력합니다. 기존 DB도 `npm run db:migrate --workspace @clario/server`로 버전 7까지 적용해야 합니다. 자세한 동작과 삭제 규칙은 [기기 명부 사용 안내](./docs/phase-2-authentication.md#학생-기기-명부-등록-추가-기능)를, 기기 코드 발급·연결·자료 전달은 [Device Client 안내](./docs/device-client.md)를 참고하세요. 이 과정은 새 학생 웹의 교실 초대코드 참여가 아닙니다.

빌드 후 저장소 루트에서 `npm start`로 API를 실행할 수 있습니다. Azure 배포 분석과 진행 상태는 [docs/azure-deployment.md](./docs/azure-deployment.md)를 참고하세요.

## Azure 자동 배포

`main` push/PR에서 GitHub Actions가 포맷·타입·테스트·전체 빌드·runtime을 검사합니다. **실제 배포는 기본 차단**이며 저장소 변수 `CLARIO_TRIAL_DEPLOY_ENABLED=true`와 운영자가 설정할 `trial` 환경 승인 규칙이 필요합니다. OIDC environment subject도 별도 검토해야 하며 이번 작업에서는 push·저장소 설정 변경·배포하지 않습니다. 과거 배포 결과는 [Actions](https://github.com/serene-jang/CLARIO/actions)에서 확인합니다.

- [교사 웹](https://thankful-flower-0c61c7200.6.azurestaticapps.net)
- [학생 웹](https://polite-desert-0eb612f00.2.azurestaticapps.net)
- [API 상태 확인](https://app-clario-dev-42e4.azurewebsites.net/health)

무료 시험 환경이며 실제 학교 운영용 서비스가 아닙니다. 기존 대시보드 미리보기와 가입 코드는 [배포 실행](https://github.com/serene-jang/CLARIO/actions/runs/39097981400)을 통해 게시됐지만, 실제 로그인에는 운영 OAuth·DB·웹/API 연결 설정이 필요합니다. 공개 화면이나 `/health` 정상만으로 교실 참여·운영 준비 완료를 의미하지 않습니다. 구성·제한·복구 방법은 [배포 문서](./docs/azure-deployment.md)를 참고하세요.
